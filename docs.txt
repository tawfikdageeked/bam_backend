# BAM REST API – Frontend Integration Documentation

## 1. Global API Rules

* **Base URL:** `[http://127.0.0.1:8080/bam](http://127.0.0.1:8080/bam)` (Update to production domain when live)
* **Content-Type:** All requests with a body (POST, PATCH) must send `Content-Type: application/json`.
* **Authentication:** The API uses JSON Web Tokens (JWT). The token must be passed in the headers of **every** protected request using the exact key `token`.
* **Tenant Isolation:** The frontend never needs to send the user's `company_id`. The backend extracts this securely from the JWT and automatically filters all database queries.

---

## 2. Authentication

### `POST /login`

Authenticates a user and generates a JWT.

**HTTP Request:**

```http
POST /bam/login HTTP/1.1
Host: 127.0.0.1:8080
Content-Type: application/json

{
    "username": "admin",
    "password": "password123"
}

```

**Responses:**

* **200 OK** (Success)
```json
{
    "token": "eyJhbGciOiJIUzI1NiIsIn..."
}

```


*Frontend Action: Save this token in memory or secure storage. Attach it to all subsequent requests.*
* **400 Bad Request**: `{"error": "No JSON in request body"}`
* **401 Unauthorized**: Invalid username or password.

## 3. Task Management

### `GET /tasks`

Retrieves a list of all tasks within the authenticated user's company, ordered newest to oldest.

**HTTP Request:**

```http
GET /bam/tasks HTTP/1.1
Host: 127.0.0.1:8080
token: <your_jwt_string>

```

**Optional Query Parameter:**
To view tasks assigned to a specific user, append `?assigned_to=<user_id>`.
*Example: `GET /bam/tasks?assigned_to=5*`

**Responses:**

* **200 OK** (Success)
```json
{
    "status": "success",
    "tasks": [
        {
            "id": 1,
            "assigned_by": 2,
            "assigned_to": 5,
            "title": "Update dashboard UI",
            "description": "Implement the new Figma designs.",
            "status": "pending"
        }
    ]
}

```



---

### `GET /tasks/{id}`

Retrieves details for a single task.

**HTTP Request:**

```http
GET /bam/tasks/1 HTTP/1.1
Host: 127.0.0.1:8080
token: <your_jwt_string>

```

**Responses:**

* **200 OK** (Success)
```json
{
    "status": "success",
    "task": {
        "id": 1,
        "title": "Update dashboard UI",
        "status": "pending"
    }
}

```


* **404 Not Found**: Task does not exist or belongs to another company.

---

### `POST /tasks`

Creates a new task.

**Business Rule (Tier Hierarchy):** The logged-in user can only assign tasks to users with an equal or lower rank (a higher tier number). Assigning a task to a superior will be rejected by the backend.

**HTTP Request:**

```http
POST /bam/tasks HTTP/1.1
Host: 127.0.0.1:8080
token: <your_jwt_string>
Content-Type: application/json

{
    "title": "Update dashboard UI",
    "description": "Implement the new Figma designs.",
    "assigned_to": 5
}

```

*(Note: `description` is optional, but `title` and `assigned_to` are required).*

**Responses:**

* **200 OK** (Success)
```json
{
    "status": "success",
    "task_id": 2
}

```


* **400 Bad Request**: `{"error": "title and assigned_to are required"}`
* **403 Forbidden**: `{"error": "Cannot assign tasks to higher tier users"}`
* **404 Not Found**: `{"error": "Target user not found in your company"}`

---

### `PATCH /tasks/{id}/status`

Updates the status of an existing task.

**Business Rule (Maker/Checker):** The backend strictly enforces what status strings can be sent based on the user's relationship to the task. The frontend should hide/disable UI buttons accordingly.

* **The Employee (The person doing the work - `assigned_to`):**
* Allowed to send: `"in_progress"`, `"submitted"`


* **The Manager (The person who created the task - `assigned_by`):**
* Allowed to send: `"completed"`, `"rejected"`



**HTTP Request:**

```http
PATCH /bam/tasks/1/status HTTP/1.1
Host: 127.0.0.1:8080
token: <your_jwt_string>
Content-Type: application/json

{
    "status": "submitted"
}

```

**Responses:**

* **200 OK** (Success)
```json
{
    "status": "success"
}

```


* **403 Forbidden**:
* `{"error": "Status update not permitted for your role on this task"}` (e.g., an employee tried to mark it "completed").
* `{"error": "You are not related to this task"}` (User is neither the assigner nor the assignee).


* **404 Not Found**: `{"error": "Task not found or not in your company"}`

---

### `DELETE /tasks/{id}`

Permanently deletes a task.

**Business Rule (Creator Only):** Only the specific manager who created the task (`assigned_by`) has the authority to delete it.

**HTTP Request:**

```http
DELETE /bam/tasks/1 HTTP/1.1
Host: 127.0.0.1:8080
token: <your_jwt_string>

```

**Responses:**

* **200 OK** (Success)
```json
{
    "status": "success"
}

```


* **403 Forbidden**: `{"error": "Task not found or you lack permission to delete it"}` (The user didn't create this task).
